# Восстановление пропусков в минутном ряде геомагнитного поля: бенчмарк и перенос между обсерваториями

Минутные записи модуля геомагнитного поля F содержат пропуски: сбои прибора,
обрывы связи, помехи. Короткие закрывает интерполяция; часовые и многосуточные
искажают расчёт индексов активности и любой анализ, которому нужен непрерывный
ряд. Здесь 3 классических способа заполнения и 12 нейросетевых архитектур
сравниваются по единому протоколу — одни окна, одни искусственные пропуски,
одни метрики — на шести обсерваториях сети INTERMAGNET.

Отчёт собирается автоматически из файлов проекта: `scripts/bench_report.py`
→ `report/Otchet_bench.docx`. Числа ниже — оттуда же; при пересчёте
меняются файлы, а не текст.

---

## Две цели

1. **Лучший метод на станции обучения** — отдельно для коротких, средних и
   длинных пропусков. Победитель зависит от длины, и один общий рейтинг это
   скрывает.
2. **Метод, который переносится на другие обсерватории без дообучения.**
   Модель обучается один раз на одной станции и в неизменном виде
   применяется к станциям с другим режимом поля — от авроральной зоны до
   экваториального электроджета. Лучшая модель «дома» и лучшая при
   переносе — как выяснилось, разные.

---

## Данные

Минутные ряды F из INTERMAGNET XML (`bench_prep.py`): F берётся из вектора
(X, Y, Z) и сверяется со скалярным магнитометром; при систематическом
расхождении больше 1 нТл берётся скаляр. Засечки (отклонение от скользящей
медианы > 100 нТл в reported-годах) и физически невозможные значения
(|F − медиана года| > 5000 нТл, любой тип данных) заменяются на NaN.
`bench_audit.py` проверяет длину каждого года по календарю, стыки лет,
покрытие.

| код | обсерватория | режим поля | F, нТл | размах в 6-сут. окне, нТл | роль |
|---|---|---|---|---|---|
| **ARS** | Арти, Урал | средние широты | 56 500 | 19 | обучение |
| WNG | Wingst, Германия | средние широты, Европа | 50 000 | 26–41 | перенос |
| CMO | College (Fairbanks), Аляска | авроральная зона | 56 300 | 88–180 | перенос |
| KAK | Kakioka, Япония | низкие средние широты | 46 800 | 28–47 | перенос |
| HUA | Huancayo, Перу | экваториальный электроджет | 24 700 | 100–180 | перенос |
| HER | Hermanus, ЮАР | южное полушарие, слабое поле (ЮАА) | 25 400 | 28–47 | перенос |

Размах — медиана разности 95-го и 5-го процентилей внутри 6-суточного окна:
то, что модель должна восстанавливать (уровень F ей известен из контекста).
ARS — станция обучения — при этом худшая по качеству данных из шести
(2016 — половина года, 2024 — 89 % покрытия); у KAK, HUA, HER пропусков нет
вовсе.

**Сплит** (одинаков для всех станций): train 2013–2016, 2018, 2020–2023
(2017 у ARS нет); val 2025 — выбор чекпойнта и конфигураций; **test 2019** —
спокойный год, минимум солнечного цикла; **test_hard 2024** — много бурь,
максимум цикла. Оба тестовых года слепые: не участвуют ни в обучении, ни в
каком-либо выборе.

Годовые файлы `data/<код>_<год>.npz` в git не идут (пересобираются из XML),
дампы предсказаний и чекпойнты — тоже.

## Постановка

- Окно 6 суток (8640 мин), патчи по 5 мин → 1728 токенов. Признаки у всех
  одинаковые: значение, маска, sin/cos суток, sin/cos года (UTC). Внешние
  индексы активности не подаются никому.
- **Обучение:** в окне несколько искусственных пропусков (первая длина — из
  распределения реальных пропусков станции обучения, остальные добираются
  до 10–30 % покрытия окна); лосс — masked-MAE только внутри искусственных
  пропусков. 12 000 шагов, эффективный батч 16, чекпойнт по MAE на
  встроенном наборе из 96 окон.
- **Тест:** один пропуск известной длины, контекст ≥ 120 мин с каждой
  стороны, 1024 окна на длину. 12 длин, три режима по четыре:
  `≤120: {5, 15, 60, 120}` · `120–1000: {240, 480, 720, 1000}` ·
  `>1000: {1440, 2160, 2880, 4320}` мин.
- Все методы получают побитово одинаковые окна; между станциями окна
  выровнены по времени (тот же год, то же начало, та же позиция пропуска),
  так что и станции сравниваются на одних событиях.
- Окна одного года перекрываются → зависимы; единица независимости —
  календарная неделя (блочный бутстрэп, ранги по ячейкам «неделя × длина»).

## Методы

| метод | семейство | что проверяет |
|---|---|---|
| **PCHIP** | классика | базлайн, точка отсчёта Score |
| Linear | классика | нижняя граница интерполяции |
| LOCF | классика | повтор последнего наблюдения |
| DLinear | линейная | нужна ли нелинейность вообще |
| U-Net | свёрточная | хватает ли локальной свёртки |
| SegRNN | рекуррентная | рекуррентность по сегментам (BRITS по отсчётам неприменим: 12 с/шаг) |
| TimesNet | периодическая | явная работа с периодом на суточно-периодичном сигнале |
| SAITS | внимание | самовнимание, спроектированное под импутацию |
| ImputeFormer | внимание | конкурент SAITS другой конструкции |
| CrossFormer | внимание | двухстадийное внимание; по вариатам вырождается (F — одна вариата) |
| CSDI | диффузия | вероятностное восстановление |
| N-HiTS | иерархическая интерполяция | многомасштабность без свёртки и без явного периода |
| N-BEATSx | интерпретируемый базис | явный тренд + сезонность |
| TSMixer | MLP-смешивание | нелинейный аналог DLinear |
| TiDE | плотный кодер-декодер | гармоники времени отдельным путём |

Обёртки в `bench_models.py` собраны из отдельных слоёв библиотек PyPOTS и
NeuralForecast, а не из готовых классов моделей — те рассчитаны на свои
загрузчики и на горизонты в десятки шагов, а не на реконструкцию окна в
1728 токенов.

**Грид гиперпараметров** (`bench_grid.py`): каждая архитектура получает один
и тот же грид — три lr (3·10⁻⁴, 10⁻³, 3·10⁻³) при размере по умолчанию, затем
размеры вдвое меньше и вдвое больше при лучшем lr; пять ячеек. Победитель —
по 1024 окнам val (среднее логарифма MAE по длинам), с предохранителем: не
проигрывает базовой ячейке значимо ни на одной длине. Победители лежат как
`models/<арх>_best.pt`, выбор — в `models/grid_selection.csv`. Заметный
выигрыш от подбора получили CrossFormer (+23 %), CSDI (+9 %), N-HiTS (+6 %);
порядок лидеров не изменился. Выбор по встроенным 96 окнам дал бы другой
результат у 7 архитектур из 12 — поэтому конфигурации выбираются по большому
набору.

## Метрики (`bench_metrics.py`, `bench_regimes.py`)

- **MAE**, **P95** (95-й процентиль абсолютной ошибки по точкам — хвост);
- **Score = 1 − MAE / MAE_PCHIP** на тех же окнах: 0 — не лучше интерполяции,
  < 0 — хуже; читается одинаково на всех длинах и станциях, по нему
  сравнивается перенос. По режимам — через геометрические средние MAE;
- **NSE, NMAE** по внутридырной дисперсии — восстанавливается ли форма
  сигнала; содержательны от 720 мин (на коротких дырах истина внутри почти
  не меняется, и знаменатель меньше ошибки любого метода);
- RMSE, RMSE_P95, MAPE — в приложении отчёта.
- **ДИ**: перцентильный бутстрэп по календарным неделям; для пары методов —
  парный интервал на разницу по одним и тем же неделям.
- **Ранги**: ячейка «неделя × длина», тест Фридмана, критическая разница
  Немени (α = 0,05), CD-диаграммы (`figures/fig_cd_<код>_<сплит>.png`).

## Результаты (кратко; полностью — в отчёте)

**Валидационный год ARS 2025, 15 методов.** Лидер по среднему рангу:
≤120 мин — PCHIP (неразличим с Linear); 120–1000 мин — U-Net (неразличим с
SAITS, CrossFormer); >1000 мин — SAITS (неразличим с U-Net, CrossFormer).
Граница «интерполяция → сеть» — 240 мин: на 5–120 мин интерполяция точнее
любой сети. Практический рецепт — гибрид: до 240 мин PCHIP, дальше сеть.

**Финалисты** (топ-5 сетей по среднему рангу на val + PCHIP, Linear):
U-Net, SAITS, CrossFormer, TimesNet, ImputeFormer.

**Слепой тест ARS 2019 и 2024** подтверждает val: лидеры режимов те же,
U-Net на длинных дырах Score +0,54 (2019) и +0,51 (2024).

**Перенос на пять станций без дообучения** — Score на длинных дырах
(>1000 мин), среднее по 2019 и 2024:

| метод | ARS | WNG | CMO | KAK | HUA | HER | падение |
|---|---|---|---|---|---|---|---|
| U-Net | 0,53 | 0,25 | 0,21 | 0,09 | 0,31 | 0,08 | −0,34 |
| SAITS | 0,52 | 0,40 | 0,15 | 0,14 | 0,37 | 0,22 | −0,26 |
| CrossFormer | 0,51 | 0,37 | 0,28 | 0,19 | 0,31 | 0,26 | −0,23 |
| **TimesNet** | 0,50 | **0,50** | **0,33** | **0,24** | 0,34 | **0,43** | **−0,14** |
| ImputeFormer | 0,50 | 0,35 | 0,22 | 0,14 | 0,30 | 0,13 | −0,28 |

- Лучшая модель дома (U-Net) переносится хуже всех; TimesNet — последний из
  пятёрки на ARS — переносится лучше всех и лидирует по рангу на длинных
  дырах на четырёх станциях из пяти в оба года.
- На средних дырах (120–1000 мин) перенос почти обнуляет преимущество
  сетей: на KAK, HUA, HER у U-Net и SAITS Score около нуля или ниже.
- На коротких дырах при переносе сети проваливаются сильнее, чем дома
  (на HUA — Score до −12): гибрид с PCHIP при переносе обязателен.
- Самые трудные станции — не авроральная CMO, а KAK и HER (другой суточный
  ход) и HUA на средних дырах.

**Обратный эксперимент** (обучение финалистов на каждой из пяти станций,
матрица «станция обучения × станция теста», leave-one-station-out) — в
работе: `bench_train.py --code <станция> --cfg models/<арх>_best.json`.

**Ограничения.** Один сид на конфигурацию; чекпойнт внутри обучения — по 96
окнам с перекосом в короткие дыры (одинаково для всех); ячейки Фридмана
делят недели, CD оптимистичен — пары проверяются парным бутстрэпом;
гиперпараметры подобраны только на ARS и заморожены при переносе; по одному
тестовому году на фазу цикла.

## Структура и воспроизведение

```
scripts/  bench_prep.py     XML -> data/<код>_<год>.npz (выбор источника F, фильтры)
          bench_audit.py    целостность: календарь, стыки лет, покрытие
          bench_common.py   сплит, окна, генератор длин пропусков, длины и режимы
          bench_models.py   архитектуры и обёртки
          bench_train.py    обучение (--code станция, --cfg конфигурация грида)
          bench_grid.py     грид lr × размер, --select по val
          bench_run.py      прогон метода -> дамп предсказаний (--align-codes)
          bench_metrics.py  метрики, Score, блочные ДИ, парные сравнения
          bench_regimes.py  Score по режимам, Фридман/Немени, CD-диаграммы
          bench_report.py   отчёт .docx из файлов проекта
data/     metrics_*.csv, regimes_*.csv (в git); ряды и дампы (не в git)
models/   *.json конфигурации и grid_selection.csv (в git); *.pt (не в git)
figures/  рисунки; report/ отчёт (не в git)
```

```bash
cd scripts
IGF_BASE=<папка с dataset_intermagnet> python -u bench_prep.py --code KAK --years 2013 2014 ... 2025
python -u bench_audit.py --code KAK
python -u bench_train.py --arch unet                          # базовая конфигурация на ARS
python -u bench_grid.py --stage 1 && python -u bench_grid.py --stage 2 && python -u bench_grid.py --select
python -u bench_run.py --method unet_best --split test --align-codes ARS,WNG,CMO,KAK,HUA,HER
python -u bench_metrics.py --pred dump_unet_best_KAK_test.npz
python -u bench_regimes.py --split test --code KAK --methods pchip linear unet_best ...
python -u bench_report.py
```

Прогон и расчёт метрик разделены намеренно: предсказания лежат на диске,
новая метрика не требует повторного запуска моделей. Окна для каждой длины
воспроизводимы независимо от того, какие длины запрошены в прогоне
(`bench_run.window_plan`).
