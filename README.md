# Восстановление пропусков в минутном ряде геомагнитного поля: сравнение методов, перенос между обсерваториями и выбор входа

Минутные записи геомагнитного поля на обсерваториях INTERMAGNET содержат
пропуски: отказы питания и связи, профилактика, сбои передачи. Короткие
закрывает интерполяция; часовые и многосуточные искажают всё, что считается
по непрерывному ряду. Здесь 10 нейросетевых архитектур и 2 классических
метода сравниваются по единому протоколу — одни окна, одни искусственные
пропуски, одна истина — на шести обсерваториях и 12 длинах пропуска от 5 минут
до 3 суток. Выводы проверены слепым тестом на двух годах по протоколу,
записанному до вскрытия тестов ([`PROTOCOL.md`](PROTOCOL.md)).

Отчёт собирается автоматически из файлов проекта: `scripts/bench_report.py`
→ `report/Otchet_bench.docx` (оба не в git). Числа ниже — оттуда же.

**Разделы отчёта:** 1 введение · 2 данные · 3 постановка · 4 методы ·
5 метрики и статистика · 6 подбор гиперпараметров · 7 рейтинг архитектур на
валидации · 8 финалисты · 9 слепая проверка на станции обучения · 10 шесть
обсерваторий: обучение на месте и перенос · 11 компоненты против модуля ·
12 разведочные наблюдения · 13 выводы · 14 ограничения · приложения А
(таблицы по длинам) и Б (конфигурации моделей).

---

## Три вопроса

1. **Какой метод брать для пропуска данной длины** на станции, где модель
   обучена, и с какой длины сеть обгоняет интерполяцию.
2. **Что даёт перенос:** работает ли модель, обученная на одной обсерватории,
   на других без дообучения, и сколько добавляет обучение на самой станции.
3. **Что подавать на вход** — модуль поля F или три компоненты X, Y, Z, из
   которых модуль собирается. Модуль скрывает направление вариации,
   компоненты его сохраняют, но втрое увеличивают размерность задачи.

**Разбиение** (одинаково для всех станций, `IGF_SPLIT=comp`):

| назначение | годы |
|---|---|
| обучение | 2014, 2015, 2016, 2018, 2020, 2022, 2025 |

Тестовые годы не участвовали ни в обучении, ни в каком-либо выборе. Самый
возмущённый год выборки (2025) отдан в обучение: сети должны видеть бури до
теста.

**Сборка.** Рецепт данных объявлен в `bench_data.py` (INTERMAGNET XML →
`bench_prep` → `bench_gin` → `bench_align`), состояние фиксируется
`data/DATA_MANIFEST.json` (в git): контрольная сумма, число минут и покрытие
каждого годового файла. `bench_data.py --check` сверяет диск с манифестом,
ничего не меняя. Годовые файлы `data/<код>_<год>.npz` в git не идут.

**Выравнивание.** В обучающих годах у станций переноса занулены минуты, где
пропуск у ARS, — обучающий бюджет у всех шести одинаков (6.36–6.42
года-эквивалента), и сравнение «своя модель против привезённой» не мерит
объём данных.

**Модуль поля.** F в файлах INTERMAGNET бывает измерен скалярным
магнитометром, а бывает вычислен как норма вектора. На College в 2021 году F
скалярный и расходится с нормой вектора на 1.9 нТл (в остальных тестовых
ячейках — 0.001 нТл), поэтому CMO 2021 исключена из сравнений «компоненты
против модуля».

## Постановка

- Окно 6 суток (8640 мин), участки по 5 мин → 1728 токенов. Признаки у всех
  одинаковые: значение, маска, sin/cos суток, sin/cos года (UTC). Внешние
  индексы активности не подаются никому.
- **Обучение:** в окне несколько искусственных пропусков, лосс — masked-MAE
  только внутри них. 12 000 шагов, эффективный батч 16 у всех архитектур;
  чекпойнт — по фиксированному валидационному набору (30 окон на каждую длину
  бенчмарка, свёртка геометрическим средним).
- **Тест:** один пропуск известной длины, 1024 окна на длину, 12 длин в трёх
  режимах: `≤120: {5, 15, 60, 120}` · `120–1000: {240, 480, 720, 1000}` ·
  `>1000: {1440, 2160, 2880, 4320}` мин.
- Все методы получают побитово одинаковые окна; между станциями окна
  выровнены по времени, так что и станции сравниваются на одних событиях.
- **Два входа.** Каждая архитектура обучается дважды: на модуле F и на
  компонентах X, Y, Z (модуль собирается из предсказанных компонент). Ошибка
  всегда считается по модулю; план окон и маска общие для обоих входов.

## Методы

| метод | семейство |
|---|---|
| **PCHIP** | классика — базлайн, точка отсчёта Score |
| Linear | классика — линейная интерполяция |
| U-Net | свёрточный энкодер-декодер |
| SAITS | самовнимание, спроектированное под импутацию |
| TimesNet | свёртка по двумерной развёртке ряда по периодам |
| ImputeFormer | внимание с проекцией длинной оси в узкое место |
| TSMixer | MLP-смешивание по времени и признакам |
| N-HiTS | иерархическая интерполяция MLP-блоками |
| DLinear | тренд + остаток, линейное отображение |
| N-BEATSx | интерпретируемый базис: тренд + сезонность |
| SegRNN | сегментная рекуррентная сеть |
| TiDE | плотный энкодер-декодер |

CrossFormer и CSDI исключены по стоимости счёта (2.5–4 ч на одно обучение
против минут у остальных). Обёртки в `bench_models.py` собраны из слоёв
PyPOTS и NeuralForecast, а не из готовых классов моделей.

**Подбор гиперпараметров** (`bench_grid.py`): одинаковый бюджет на
архитектуру — три скорости обучения (3·10⁻⁴, 10⁻³, 3·10⁻³) при среднем
размере, затем три размера при выбранной скорости; 5 обучений × 10
архитектур. Победитель — по 1024 окнам валидации с правилом допуска: не
проигрывает базовой ячейке значимо ни на одной длине (парный бутстрэп).
Выбор — `models/comp/grid_selection.csv`. Подбор выполнен на входе-модуле;
компонентные модели используют те же конфигурации.

**Финалисты** — пять архитектур по среднему рангу на валидации: U-Net,
SAITS, TimesNet, ImputeFormer, TSMixer. Они же обучены на каждой из пяти
других станций при обоих входах.

## Метрики и статистика (`bench_metrics.py`, `bench_regimes.py`, `bench_verdict.py`)

- **MAE** внутри пропуска — основная; RMSE, P95, NSE (от 720 мин) — рядом.
- **Score = 1 − MAE / MAE_PCHIP** на тех же окнах: 0 — как интерполяция,
  0.5 — ошибка вдвое меньше, < 0 — хуже. По режимам — через геометрические
  средние MAE.
- **Парный блочный бутстрэп** по календарным неделям (2000 повторов): окна
  внутри недели зависимы, поэтому пересобираются недели. Каждое сравнение
  «A точнее B» имеет три исхода: значимо точнее, неразличимо, значимо хуже.
- **Ранги** по ячейкам «неделя × длина», Фридман и Немени, CD-диаграммы
  (`figures/fig_cd_*.png`). Ячейки одной недели зависимы, поэтому порог
  Немени — только ориентир; утверждения протокола решаются бутстрэпом.
- **Связи** по 5–6 станциям — ранговая корреляция Спирмена с точным
  перебором перестановок; исходы: подтверждено, опровергнуто, не доказано.

## Слепой тест

Протокол записан в git до вскрытия тестов: 15 утверждений, у каждого —
условие опровержения. Утверждение подтверждено, только если выполнено в обоих
годах; выполнено в одном — «зависит от обстановки». Вердикты считает
`bench_verdict.py`, результаты — `data/comp/verdict_test*.json`.

**Счёт: подтверждено — 10, зависит от обстановки — 1, не доказано — 3,
опровергнуто — 1.**

### 1. Метод по длине пропуска (ARS)

- **До 60 мин** PCHIP значимо точнее каждой сети пятёрки — 15 из 15
  сочетаний «сеть × длина» в обоих годах. На 5 мин даже самая точная сеть
  ошибается в 3.3–3.4 раза больше.
- **От 480 мин** каждая сеть значимо точнее PCHIP — 35 из 35 в обоих годах.
  На пропусках от суток медианный Score по пятёрке +0.52 (2021) и +0.48
  (2024); в возмущённой половине окон исключений 0 из 20.
- **120–240 мин** — переходная зона, граница зависит от архитектуры.
- Выигрыш по RMSE меньше, чем по MAE (+0.39 и +0.32), и в бурный год падает
  сильнее: сеть промахивается редко, но крупно.
- Состав пятёрки, отобранной на валидации, сохранился на обоих входах в обоих
  годах. Порядок внутри пятёрки не утверждается.

### 2. Шесть обсерваторий: обучение на месте и перенос

Score на пропусках от суток, медиана по пятёрке:

| станция | обучение на месте, 2021 | 2024 | перенос с ARS, 2021 | 2024 |
|---|---|---|---|---|
| WNG | +0.595 | +0.590 | +0.371 | +0.348 |
| CMO | +0.365 | +0.349 | +0.202 | +0.204 |
| KAK | +0.429 | +0.426 | +0.142 | +0.132 |
| HUA | +0.632 | +0.681 | +0.367 | +0.321 |
| HER | +0.559 | +0.585 | +0.208 | +0.127 |

- При обучении на месте каждая сеть значимо точнее интерполяции на длинных
  пропусках на каждой станции и при обоих входах — исключений 0 из 200.
- **Станции различаются сильнее, чем архитектуры:** медианы по станциям
  расходятся на 0.27–0.33, пять сетей внутри станции — не больше чем на 0.06.
- NSE сетей следует доле регулярного суточного хода на станции: ρ = +0.83 и
  +1.00. В бурный год NSE значимо падает только на ARS и WNG; на HUA и HER,
  где регулярного хода больше всего, почти не меняется.
- **Перенос с ARS** без дообучения работает только на длинных пропусках: от
  суток — значимый выигрыш у всех пяти моделей на каждой станции, на 240–720
  мин — ни у одной, в обоих годах.
- Обучение на месте значимо точнее переноса на всех пяти станциях, выигрыш
  21–56 %. Связь величины выигрыша с разницей наклонения поля — не доказана
  (пять точек).
- Перенос несимметричен (15 из 15 пар в 2021, 13 из 15 в 2024), но
  предсказанный заранее порядок станций не подтвердился: модели с HUA
  переносятся хуже всех, а лучшей целью оказалась WNG, худшей — HUA.
  Полная матрица 6 × 6 для обоих лет — раздел 10.4 отчёта.

### 3. Модуль или компоненты

- **Зависит от обстановки.** В спокойном 2021 компоненты значимо точнее
  модуля у U-Net, SAITS, ImputeFormer и TSMixer; в бурном 2024 выигрыш
  сохранился у ImputeFormer и TSMixer, исчез у U-Net и сменился проигрышем у
  SAITS; у TimesNet разницы нет ни в одном году.
- По величине выигрыш небольшой: на валидации наименьшая ошибка на длинных
  пропусках снижается на 2.4 %.
- Связи пользы компонент с силой архитектуры и с наклонением поля на
  станции значимы только в одном году из двух — не доказаны.

**Практический итог:** пропуски до часа — интерполяцией, от 8 часов — сетью;
для новой обсерватории лучше обучить модель на её данных, готовая модель с
другой станции годится только для пропусков от суток; если нужен только
модуль, модуль на входе — надёжный вариант по умолчанию. Компонентная модель
восстанавливает весь вектор X, Y, Z, но точность отдельных компонент в
бенчмарке не измерялась — сравнение шло по модулю.

**Как выглядит восстановление** — рисунки «типичное окно»
(`figures/gap_examples/fig_examples_comp_ARS_<сплит>_L<длина>.png`): из 1024
окон берётся медианное по средней ошибке пяти сетей, длины 60, 720 и 2880
мин, панели X, Y, Z и модуль.

**Ограничения** (полностью — раздел 14 отчёта): подбор гиперпараметров
только на входе-модуле и только на ARS; у семи архитектур из десяти выбор
стоит на краю сетки; у 5 моделей из 20 лучший чекпойнт — на последнем шаге
бюджета; один сид на конфигурацию; связи с геофизикой станций проверены на
5–6 точках, поэтому «не доказано» значит «мало точек», а не «связи нет»;
индекс возмущённости вычислен по самим данным, а не по Kp или Dst.

## Воспроизведение

Переменная `IGF_SPLIT` обязательна для каждого скрипта. Команды для
PowerShell, из папки `scripts`:

```powershell
$env:IGF_SPLIT = 'comp'
python -u bench_data.py --check                                            # данные соответствуют манифесту
python -u bench_grid.py --stage 1; python -u bench_grid.py --stage 2; python -u bench_grid.py --select
python -u bench_train.py --arch unet --code WNG --cfg ../models/comp/unet_best.json --out ../models/comp/unet_WNG_best.pt          # модель на станции
python -u bench_train.py --arch unet --code WNG --cfg ../models/comp/unet_best.json --comp --out ../models/comp/unet_WNG_best_xyz.pt   # то же, компоненты
python -u bench_run.py --method unet_best --code WNG --split test --n 1024                   # перенос ARS -> WNG
python -u bench_metrics.py --pred dump_unet_best_WNG_comp_test.npz --no-fig
python -u bench_regimes.py --code ARS --split test --tag Fbest --methods unet_best saits_best pchip linear
python -u bench_verdict.py --split test --test-ok
python -u bench_verdict.py --combine --test-ok
python -u bench_examples_comp.py --code ARS --split test --style report
python -u bench_report.py
```

`bench_run.py` по умолчанию берёт 128 окон на длину — для бенчмарка всегда
`--n 1024`. Прогон и расчёт метрик разделены намеренно: предсказания лежат на
диске, новая метрика не требует повторного запуска моделей. План окон
детерминирован зерном и не зависит от того, какие длины запрошены.
